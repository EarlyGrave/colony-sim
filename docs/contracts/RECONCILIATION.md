# Contract reconciliation (architect proposal)

Resolves the 10 items in section 3 of `docs/contracts/README.md`. Each row: issue, ruling, files to edit next session, rationale.
Related contracts: `items-inventory.md`, `recipes-buildings.md`, `colonists-needs-jobs.md`, `combat-weapons.md`, `research-events-save.md`.

| # | Issue | Proposed ruling | Files to edit in the next session | Rationale |
|---|---|---|---|---|
| 1 | `recipe` vs `recipes` on building defs | Canonical field is `recipes` (array of recipe ids). `recipe` is removed everywhere; `Defs` loader asserts/warns if `recipe` is still present. Also keep both signals `building_placed` (blueprint placed) and `building_completed` (construction finished) with these distinct meanings. | `data/buildings.json`, `sim/core/defs.gd`, `sim/buildings/building.gd`, `sim/buildings/building_system.gd`, `autoload/event_bus.gd`, `tests/test_buildings*.gd`, `docs/contracts/recipes-buildings.md` | Only recipes-buildings uses the field, so migrating is cheap. Two signals keep the blueprint stage (jobs, UI ghost) separate from "building is usable" (production, power, turrets). |
| 2 | Skill ids differ (`none`, missing `plants`/`shooting`/`melee`) | Canonical skill list is the 9 in colonists-needs-jobs.md: mining, construction, crafting, smelting, shooting, melee, medicine, cooking, plants. `none` is not a skill: recipe/building `skill` is nullable (`null` or omitted = no skill requirement). Defs validation rejects any other id. | `data/skills.json`, `docs/contracts/recipes-buildings.md` (enum), `docs/contracts/combat-weapons.md` (check), `sim/core/defs.gd` (validation), `data/recipes.json`, `data/buildings.json` | `skills.json` is the single source of truth; a sentinel value inside an enum of skills breaks XP and skill lookups. |
| 3 | Storage priority scale and "priority" name clash | Storage priority is an int enum `0..3` named `low=0, normal=1, high=2, critical=3`, stored per zone/container as `storage_priority`. Per-zone integer (open Q7) is rejected. Work priority (colonists) is a separate scale and uses the key `work_priority` in UI/save. The bare key `priority` is not used for either. | `sim/items/item_system.gd`, `sim/items/storage_priority.gd` (new enum), `data/rules.json`, `docs/contracts/items-inventory.md` (close Q7), `docs/contracts/colonists-needs-jobs.md` (rename key), `view/` zone panel | Four levels are enough for hauling decisions and are touch-friendly; distinct key names avoid save/UI collisions. |
| 4 | Equipment commands: `equip()` (combat) vs `equip_item` (items) | One command: `Simulation.equip_item(colonist_id, item_id)` (and `unequip_item`). It queues the EquipJob internally. combat-weapons `equip()` is dropped from the public API. Equipment state lives in `Colonist.inventory.equipment` (slots weapon/armor). | `sim/core/simulation.gd`, `sim/jobs/equip_job.gd`, `sim/colonists/colonist.gd`, `sim/threats/*` (callers), `docs/contracts/combat-weapons.md`, `docs/contracts/items-inventory.md`, `tests/test_equipment*.gd` | CLAUDE.md requires one command entry point per player action through `Simulation`; items owns inventory, so it owns the verb. |
| 5 | Weapons/armor: item `category` vs separate `weapons.json`/`armor.json` | Weapons and armor are items with `category` = `weapon` or `armor` in `data/items.json`. Extra combat stats live in `data/weapons.json` and `data/armor.json`, keyed by the same id as the item (item id == weapon id). No link field. `Defs` validates that every key in those files exists in items with matching category, and vice versa. | `data/items.json`, `data/weapons.json`, `data/armor.json`, `sim/core/defs.gd`, `sim/items/item_system.gd`, `docs/contracts/items-inventory.md`, `docs/contracts/combat-weapons.md`, `tests/test_defs*.gd` | Matching ids need no extra field and no lookup table; validation catches drift. Items stay generic and combat data stays out of the item schema. |
| 6 | `order_attack` signature and `shot_fired.shooter_kind` | Final signature: `order_attack(colonist_id: int, enemy_id: int)` (no `target_kind`). `shot_fired` keeps `shooter_kind: int` (enum: 0 colonist, 1 turret, 2 enemy) and documents the enum in `event_bus.gd`. Strike the old signature from the doc history. | `sim/core/simulation.gd`, `sim/threats/threat_system.gd`, `autoload/event_bus.gd`, `docs/contracts/combat-weapons.md`, `view/world_view.gd` (shot listener) | Colonists only attack enemies; shooter kind still needed because turrets and enemies also fire. |
| 7 | Injury path vs "hp <= 0 = death" | Combat damage produces injuries only: combat calls `sim.colonists.injure(colonist_id, body_part, severity, source)` and emits `colonist_injured`. Death occurs only through the health model (colonists contract): hp is derived from injuries, and death/downed transitions are decided there. The combat doc line "downed out of scope: hp <= 0 = death" is removed; downed state is owned by colonists. | `sim/colonists/health.gd`, `sim/colonists/colonist_system.gd`, `sim/threats/enemy.gd`, `sim/threats/threat_system.gd`, `autoload/event_bus.gd`, `docs/contracts/combat-weapons.md`, `docs/contracts/colonists-needs-jobs.md`, `tests/test_health*.gd`, `tests/test_combat*.gd` | A single owner of death avoids two parallel hp models and keeps medicine/treatment meaningful. |
| 8 | Ledger reason vocabularies | Unify in one controlled enum in `sim/core/ledger.gd` (`Ledger.Reason`): existing reasons plus `construction`, `item_produced`, `item_consumed`. Free-form `source`/`sink` strings become a separate optional `tag` field for diagnostics only; they never drive logic or tests. All new reasons must be added to the enum and to the balance report. | `sim/core/ledger.gd`, `sim/items/item_system.gd`, `sim/buildings/building_system.gd`, `tools/balance_report.gd`, `docs/contracts/items-inventory.md`, `docs/contracts/recipes-buildings.md`, `tests/test_ledger*.gd` | A closed vocabulary keeps accounting queryable and deterministic; free text is fine as annotation only. |
| 9 | Save contract misses new state | Keep research-events-save rule: `to_dict`/`from_dict` per system, ids-only data. Save contract must add: inventories (including equipment), storage zone settings (`storage_priority`), blueprints, production orders, injuries, work priorities (`work_priority`), drafted flag, and turret ammo. Each system owns its serialization; a round-trip test per system plus a whole-game "save, load, step N ticks, compare" test is required. Save version bumps with each new field set. | `sim/core/simulation.gd` (aggregate), `sim/items/item_system.gd`, `sim/colonists/colonist.gd`, `sim/colonists/colonist_system.gd`, `sim/buildings/building_system.gd`, `sim/threats/threat_system.gd`, `docs/contracts/research-events-save.md`, `tests/test_save*.gd` | Save is last in the reading order precisely because it must cover everything; listing the state now prevents silent data loss. |
| 10 | Events: `story_event` shape vs Mood stub | `story_event` signal args are frozen: existing arguments stay in the same order and type. Text moves to data (`data/events.json`) by adding a new optional trailing argument or a separate lookup by event id, never by reshaping existing args. `Storyteller.PREDICATES` and the journal stay in `sim/storyteller` + `sim/story`; Mood listens by event id only. | `autoload/event_bus.gd`, `sim/storyteller/storyteller.gd`, `sim/story/*`, `sim/colonists/mood.gd`, `data/events.json`, `docs/contracts/research-events-save.md`, `docs/contracts/colonists-needs-jobs.md`, `tests/test_storyteller*.gd` | Stable signal args let the research/events refactor and the colonist Mood stub land independently. |

## Cross-cutting rules after reconciliation

- Every ruling above supersedes the older text in the individual contract; edit the contracts to match before coding the stage.
- Each ruling that changes data gets a Defs validation plus a test; the runner already fails on any engine error.
- Reports to the owner remain in Russian; this file stays in English.
