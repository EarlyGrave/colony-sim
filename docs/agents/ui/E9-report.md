# Отчёт агента ui, этап E9

## Что сделано
- Написан контракт `docs/contracts/ui-touch.md` для тач-интерфейса этапов E10-E21: список из 8 панелей
  (меню стройки, карточка колониста, панель здания, приоритеты работ, дерево исследований, журнал и тревоги,
  боевой режим, фильтр зоны хранения) с тем, какое состояние sim каждая читает и какую команду `Simulation` шлёт.
- Правила: view только читает, все строки через `tr()` с ключами `ui.<panel>.<element>`, структура
  `translations/*.csv` (en, ru), тап-цели >= 64 px, проверка на 390x844 и 1024x768, на телефоне одна панель.
- Раздел "polling vs bus": какие панели опрашивают sim, каким нужны сигналы шины.
- Открытые вопросы для оркестратора (9 пунктов).
- Код не менялся. Из `view/hud.gd` просмотрен только список функций (времени было мало, ~3.5 мин).

## Решения
- Новые команды помечены (proposed): их надо завести владельцам систем; существующие - `designate_mine`,
  `set_zone`, `place_building`, `set_alarm`, `set_rule`.
- Журнал событий и тревоги обязаны идти через сигналы шины (опрос теряет/дублирует события).
- Переводы лежат в `translations/ui.csv`, `content.csv`, `events.csv`; в JSON данных хранятся ключи
  (`name_key`), а не готовый текст.
- Опрос ограничен 2-4 Гц и только у видимых панелей; списки перестраиваются только по структурным сигналам.
