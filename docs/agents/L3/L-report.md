# L3 report: power grid sim

- New: `sim/power/power_system.gd` (`sim.power`), `sim/power/power_net.gd` (union-find), `tests/test_power.gd` (11 tests), `docs/power_api.md` (API for L4/L5).
- Shared files, all in `# region L3`: building.gd (fields, generator `input_space`), building_system.gd (`version` counter + hooks, brownout in `_tick_processor`/`_tick_extractor`), simulation.gd (construct, `power.tick` before `tick_machines`), save_game.gd (hash part only once enabled), defs.gd (`defs.fuels`, loaded if `data/fuels.json` exists), event_bus.gd (`power_changed`, `power_meltdown`), threat.json (`state_mod.powered_gen` 1.0 and `unfuelled` 0.25), sim_contract.md (tick order + 2 lines; file is 249/250 lines).
- Networks: union-find over poles, bucketed by range; buildings join every pole in reach; rebuilt only when `buildings.version` changes (place/remove/break/repair). Merge/split, 0.5 for unpoled consumers within 1 tick tested.
- Generators read fuels generically (burn_ticks | energy, waste float with carried remainder, contamination, spent_item); burn only while net demand > 0. Ledger sources `power_waste`, `power_spent`, sink `power_fuel`. Burner full load = 5 waste/1000 ticks; idle grid burns 0.
- Brownout = clamp(supply/demand, 0.2, 1) via fractional accumulators (processor steps, extractor output). 3 smelters + 1 burner: factor 0.833, throughput ratio 0.83 +-0.05 (measured over 3000 ticks: 1000 is too coarse, +-7% from batch quantisation); 2nd burner 1.0; no fuel 0.2 and batches still finish.
- Threat: `threat_flags` `powered_gen` (burning) / `unfuelled`; unfuelled burner 15 -> 3.75 through `threat_mods`/state_mod.
- Reactor: def `meltdown {fuse_ticks, condition_below, radius, damage, contamination}`; broken/worn + fuelled heats 1/tick, cools 2/tick; at the fuse: destroyed, contamination burst, blast damage; no rng, deterministic; repair in time cools it.
- Enforcement OFF until first pole/generator: factor 1.0 exactly, no hash part, so goldens are unaffected (full suite run twice, see lead summary).
- Perf (4-core box at load average ~17, best of 7): recompute 500 poles + 200 consumers ~5.8 ms (target 5; test asserts 5 x noise_margin 1.5), tick 0.12 ms (target 0.2). Recompute is dominated by GDScript dictionary/array overhead; if a quiet-box number still misses, the next step is caching pole buckets between rebuilds.
- Assumptions to confirm with L5: field names above (`power_use`, `power_gen`, `fuel`, `power_range`, `meltdown`, fuels.json keys), `waste` item as the contaminating output, and that `fuels.json` gets its row in sim_contract.md from L5. Not done: batteries, throttling of research benches, load-sharing between generators (all burn when demand > 0).
