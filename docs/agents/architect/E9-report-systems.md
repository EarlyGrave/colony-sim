# Отчёт архитектора E9: системы (исследования, события, журнал, сохранения)

## Что сделано
Написан контракт `docs/contracts/research-events-save.md` для этапов E18-E20:
схема `data/research.json` (с правилом: тир >= 3 стоит `refined_essence`),
расширенная схема колоды событий (`condition` / `weight` / `effect` / `journal_text`
/ `alert`) и 6 стартовых событий, журнал `sim/story/journal.gd`, сохранение
`sim/save/save_system.gd` с тестом детерминизма, новые сигналы шины, открытые вопросы.
Код и существующие документы не менялись.

## Принятые решения
| Решение | Выбор | Почему |
|---|---|---|
| Условия событий | список именованных предикатов (AND), без строковых выражений | нет eval/парсера в sim, легко тестировать |
| Эффекты событий | типизированный `effect.type`, один эффект на событие | сохраняет D15: одно событие — одно звено |
| Текст в журнале | `text_key` + `args`, показ через `tr()` | локализация, JSON-безопасные сохранения |
| Журнал | append-only, лимит 500, не входит в хэш состояния | чистый лог, не влияет на симуляцию |
| Исследование | команда `Simulation.set_research(id)`, работа через `ResearchJob` у стола | единый путь команд, возможны реплеи |
| Сохранение | `to_dict()/from_dict()` у каждой системы, файловый I/O только во view | sim остаётся чистым RefCounted |
| RNG в сохранении | `seed` + `rng.state` строкой (64-бит не влезает в JSON number) | иначе теряется точность |
| Автосохранение | раз в игровой день, 2 ротируемых слота + 3 ручных | лимиты IndexedDB в вебе |
