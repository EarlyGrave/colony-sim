# E9: отчёт архитектора по предметам и хранению

## Что сделано
- Написан контракт `docs/contracts/items-inventory.md`: схема предмета, модель стеков, хранение (фильтры и приоритеты), закон сохранения через `Ledger`, сигналы шины, команды игрока, открытые вопросы.
- Код и существующие документы не менялись.
- Прочитаны `data/items.json`, `data/zones.json`, `sim/core/ledger.gd`, `sim/core/defs.gd` и публичный API `sim/items/item_system.gd`.

## Принятые решения (таблица)

| Решение | Выбор | Причина |
|---|---|---|
| id предметов | оставить `essence_ore`, `refined_essence`, `waste` | переименование затронет рецепты, здания, зоны, тесты, спрайты без пользы |
| Схема предмета | `name`, `category`, `weight`, `stack`, `tags`, `icon`, опц. `contaminates`, `color`, `slot` | расширение текущего `items.json`, валидация в `Defs` |
| Стек | одна запись на клетку, не больше `stack` единиц | прежнее решение |
| Владельцы | земля и зоны: `ItemSystem`; инвентарь: `Colonist.inventory`; буферы: `Building` | один владелец на место хранения |
| Приоритеты | low/normal/high/critical, перенос только в строго более высокий | нет «пинг-понга» между складами |
| Фильтры | `categories` поверх `accepts` из `zones.json` | обратная совместимость |
| Ledger | перемещения не трогают ledger; источники: mining, recipe, event, start; стоки: recipe, consumption, destroyed, lost | инвариант сохранения |
| Настройки зоны | per-instance (предложено) | см. запросы |

## Заглушки и долги
- Ничего не реализовано, только контракт.
- `Ledger.check(...)` и `ItemSystem.world_count_all()` описаны, но не написаны.
- Значения `weight` для трёх существующих предметов (1.0 / 0.5 / 2.0) взяты с потолка, нужен баланс.
- Документ писался в сжатые сроки: баланс-ключ лимита переноса не сверен точно (в `balance.json` сейчас `carry_capacity: 10`).
