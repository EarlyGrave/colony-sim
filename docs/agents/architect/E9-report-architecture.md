# E9 — отчёт архитектора

## Что сделано
- Проведён быстрый аудит текущего кода (`autoload/event_bus.gd`, `sim/core/*`, по одному-два файла из каждой системы, `view/game.gd`) и записан в `docs/ARCHITECTURE.md`.
- В документе: карта систем, порядок тика и вызывающий `step()`, таблица всех сигналов EventBus (кто эмитит / кто слушает), список команд игрока в `Simulation`, таблица data-файлов и загрузчика, правила детерминизма как они реализованы, точки расширения для E10–E22.

## Принятые решения
- Документ описывает фактическое состояние кода, а не план; расхождения с `CLAUDE.md` отмечены (напр., `GameController` на деле `view/game.gd`).
- Точки расширения даны одной строкой: каталог + шина, без проектирования API.

## Изменённые и созданные файлы
- Создан `docs/ARCHITECTURE.md`.
- Создан `docs/agents/architect/E9-report-architecture.md`.
- Код и существующие документы не менялись.

## Заглушки и долги
- Аудит быстрый (дедлайн ~6 минут): не проверялись все `for ... in dict` в `sim/` на детерминизм, не читались тесты и `tools/`.
- Большинство сигналов шины не имеют слушателей (HUD опрашивает состояние), это зафиксировано, но не оценено.
- `ThreatSystem` зависит от ключей Ledger (`mining:essence_ore`, `recipe:refined_essence`) — неявный контракт.
- У систем нет `to_dict/from_dict`, сохранения пока невозможны.
- Нет команд для части действий (снос, приоритеты работ) — см. раздел 4.
