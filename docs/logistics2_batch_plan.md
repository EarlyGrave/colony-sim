## Frozen schema (everyone codes against this; L5 lands the data first, others inject identical defs in tests until merged)
- Belt node kinds (`BeltGrid.kind: PackedByteArray`, 0 = plain belt): 1 splitter_basic, 2 splitter_smart, 3 splitter_priority, 4 merger. 1x1 cells that sit in the belt grid (NOT Buildings: 8k-belt perf), `dir` = flow direction.
  Splitter: input from the back cell, outputs = front, left, right neighbours that hold a belt not pointing back into the node. Merger: inputs = back, left, right; one output = front.
- Smart filter per output slot (0=left,1=front,2=right): `"any"` | `"overflow"` | item id. Defaults `any`. Item with a matching explicit filter beats `any`; `overflow` receives only if all matching/any outputs are blocked.
- Power defs in `buildings.json`: consumer `power_use` (units/s), generator `power_gen` + `fuel` {item, burn_ticks, waste_per_burn} (or `fuel: null` for passive), pole `power_range` (cells, link radius pole<->pole and pole<->building footprint).
- New defs: `power_pole` (1x1, range 6), `essence_burner` (2x2, gen 100, fuel essence_ore/200 ticks, waste 1 per burn, threat 15), `solar_array` (2x2, gen 25, no fuel, no waste, threat 4). Consumers: miner 20, smelter 40, assembler 50, research_bench 20, +10 per installed AI chip.
- New techs (research.json): `splitting` (T1, prereq conveyance: splitter_basic, merger), `smart_logic` (T2, prereq splitting+filters: smart, priority), `electrification` (T1, prereq smelting+conveyance: power_pole, essence_burner), `clean_power` (T3, prereq electrification+advanced_recipes: solar_array).

## L1 splitters + merger sim
Owns `sim/logistics/belt_grid.gd` (region L1), `sim/logistics/belt_node.gd` (new), `sim/logistics/logistics_system.gd` (region L1), `tests/test_splitters.gd`.
- Node holds 1 item like a belt cell; when ready it picks an output: basic = round-robin pointer (per node, advances only on success), priority = first non-blocked of [front, left, right] order by slot index, smart = rules above. Merger alternates between inputs that have a ready item (pointer per node). Fixed ascending cell-index order, no rng, no Dictionary-order dependence (arrays + sorted ids only).
- Command-facing API (called by L2): `place_node(kind, cell, dir)`, `remove_node(cell)`, `set_filter(cell, slot, value)` stored in sparse `filters: Dictionary[int cell -> PackedStringArray(3)]` (iterated sorted).
- `state_hash` / `state_parts` change ONLY when at least one node exists: with none, hash is byte-identical, `tests/golden/*.json` untouched (test: run golden scenarios, 0 diffs). Bump `version` on node place/remove/filter change. Sparse stepping stays: nodes join `_occ` like belts.
- Accept: conservation (inserted == extracted + destroyed + item_count) over 2000 ticks with 3 splitters + 2 mergers in a looped lattice; basic splitter 300 items -> outputs 150/150 +-1, with one output blocked all go to the other with 0 loss; priority: out1 free -> 100% out1, out1 blocked -> 100% out2, out1 reopens -> back to out1 within 1 tick; smart: iron_ore filter on out1 + `any` on out2 -> 100% of iron on out1 (any other item never on out1), `overflow` on out3 receives only when out1/out2 blocked; merger 2 saturated inputs -> each contributes 50% +-2%; same setup twice -> equal `state_hash` at ticks 100/500/2000; perf: 8000 belts + 200 splitters (mixed kinds, flowing) `logistics.tick()` <= 1.0 ms avg over 300 ticks (add to `tests/perf_budget.json`, `tools/belt_bench.gd` row).

## L3 power grid sim
Owns `sim/power/power_system.gd` (new), `sim/power/power_net.gd` (new), `sim/buildings/building.gd` (region L3: `power` fields), `sim/buildings/building_system.gd` (region L3: hooks), `sim/core/simulation.gd` (region L3: construct system, tick, signals), `sim/core/save_game.gd` (region L3: hash part), `data/threat.json` (only `state_mod.powered_gen` key), `tests/test_power.gd`.
- Tick: `power.tick` right before `buildings.tick_machines` (document in sim_contract tick order). Networks = union-find over poles and powered buildings; link if distance(pole, pole) <= max(range) or pole to nearest footprint cell <= pole range. Recompute ONLY when `buildings.version` (add counter bumped in place/_remove/destroy/broken change) changes; per tick only sum supply/demand per net (arrays, id order).
- Generators: fuel from `input` buffer (hand-fed or belt port), burn one unit every `burn_ticks` ONLY while its net demand > 0 (idle grid burns nothing); each burn adds `waste_per_burn` to contamination through the existing refinery waste path (ledger source `power_waste`) so forecast model counts it; no fuel/broken/destroyed -> 0 supply. Solar: constant supply, 0 waste. No batteries (decided: later).
- Brownout: `factor = clamp(supply/demand, min_factor 0.2, 1)` per net, applied as fractional step accumulator (same pattern as `ChipSystem.steps`) to processor work steps and extractor `mach_acc`; belts and ports never need power. Consumer not within any pole range: `unpowered_factor` 0.5. Enforcement is OFF until the first pole or generator exists (flag in state), so old scenarios/goldens are unchanged.
- Threat: generator `threat` value from data (burner 15 running, x0.25 when out of fuel via `threat_mods`); contamination of waste raises waves as today. Bus signals `power_changed(net_id)` only on change of factor bucket (0.05), never per tick.
- Accept: 3 smelters + 1 burner (100) vs demand 120 -> factor 0.833 +-0.01 and measured recipe throughput ratio 0.83 +-0.05 over 1000 ticks; add a 2nd burner -> 1.0; burner without fuel -> factor floor 0.2, never 0 (machines still finish batches); idle grid (no demand) burns 0 fuel over 1000 ticks; break pole in a chain -> network splits, far machines drop to 0.5 within 1 tick; burner waste per 1000 ticks at full load = 5 +-0.5 units and shows in contamination; deterministic `state_hash` equal across 2 runs and after save/load; with no pole/gen all 8 goldens byte-identical; `power.tick` <= 0.3 ms with 300 machines + 40 poles (perf_budget.json).
